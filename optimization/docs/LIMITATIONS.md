# Limitations

- **First use is slower for Rust than packaged Python-fast.** The fastest packaged resident variant needs an existing native bundle, full integrity checks, and original source estimators. Bundle conversion adds a separately measured one-time cost. Starting a new process for every request does not amortize those costs in the recorded scenario.
- **The evidence covers one completed CPU allocation and specific workloads.** There are five resident observations per main arm and three fresh-process trials per lifecycle variant. OS caches were uncontrolled. These samples support the reported descriptive statistics, not universal speedups, p95, statistical significance, or GPU claims.
- **Memory remains substantial.** Standalone serving peaks were approximately 7.43 GiB for packaged Python and 10.80–10.86 GiB for packaged Rust. Conservative cache accounting is not measured RSS. Both load and mmap retain original estimators and charge full numeric bundle capacity.
- **The conservative backend still unpickles trusted source models.** The numerical bundle avoids repeated array export; it does not provide model-object-free or pickle-free serving. A replacement validator was not implemented or tested. Source models must match the verified bundle.
- **Concurrency is explicitly unsupported within an instance.** The API rejects overlapping prediction and lifecycle operations. This project did not test parallel serving, GPU prediction, a service deployment, or production concurrency behavior.
- **Chunking is a retained negative result.** Chunks 64 and 256 produced exact outputs and reduced FFI calls, but were slower than chunk 1. The recorded diagnostic intervals do not establish one cause for the full slowdown.
- **Correctness claims are bounded by executed comparisons.** The 92-record census includes 65 direct checks, 25 resident checks linked to accepted first outputs, and two original oracle runs. The regression cases extend coverage but do not establish equivalence for every possible input. The saved author CSV is tolerance-equivalent rather than bit-exact; fresh-original comparisons were exact.
- **The expanded workload evidence is a pilot.** One real column and 32 deterministic synthetic columns were tested for 1,024 targets. The full-target expansions were skipped under the recorded runtime-budget rule. No new biological measurements or accuracy improvements are claimed.
- **Compatibility is tied to the recorded legacy stack and Linux native build.** The exact inference dependency freeze is preserved. `-C target-cpu=native` produces a machine-specific binary, so rebuild on the intended host. No binary, environment, model archive, or native bundle is published here.
- **Publication checks are source and evidence checks.** They regenerate figures and verify hashes, data schemas, syntax, and package layout. Historical model-dependent regression evidence is preserved; it was not rerun during closeout.

See [Methods](METHODS.md) for controls, timing boundaries, and correctness definitions, and [Results](RESULTS.md) for measured trade-offs.
